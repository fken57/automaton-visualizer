# Automaton Studio

有限オートマトンをGUI・3つ組記法・矢印記法で相互編集し、図をワンクリックでPNG保存するWebアプリです。日本語UI、DFA / NFA / ε遷移、受理シミュレーション、ドラッグ編集、自動配置、Undo / Redo、JSON入出力、ブラウザへの自動保存に対応します。

## 起動

Node.js 22以上で実行します。外部パッケージのインストールは不要です。

```sh
npm run dev
```

http://localhost:5173 を開きます。

```sh
npm test
npm run build
npm start
```

`dist/` にHTML・CSS・JavaScriptの静的ファイルが出力されます。`npm start` はその成果物を配信します。`PORT` 環境変数でポートを指定できます。サブディレクトリへの配信にも対応します。

## NeoShowcaseへデプロイ

GitHubまたはGiteaのリポジトリにこのディレクトリのファイルを置いて、NeoShowcaseに登録します。アカウント・リポジトリ・公開先の設定は利用環境に合わせてください。

### 静的サイトとして配信（推奨）

NeoShowcaseのビルド方法を「Static (command) / 静的・コマンド」にします。

| 設定 | 値 |
| --- | --- |
| ベースイメージ | `node:22-alpine` |
| ビルドコマンド | `npm run build` |
| 成果物のパス | `dist` |
| 作業ディレクトリ | このプロジェクトのルート |
| 環境変数・DB | 不要 |

別のリポジトリのサブディレクトリに置く場合は、ビルドコマンドを `cd automaton-visualizer && npm run build`、成果物のパスを `automaton-visualizer/dist` とします。ダッシュボードの項目名やパスの指定方式は利用中のNeoShowcaseのバージョンで確認してください。

### Dockerfileで配信

「Runtime (dockerfile) / ランタイム・Dockerfile」、Dockerfileを `Dockerfile`、ビルドコンテキストをこのディレクトリ、Webサイトの転送先ポートを **8080** に設定します。サブディレクトリ配置の場合もビルドコンテキストをこのプロジェクトにしてください。

```sh
docker build -t automaton-studio .
docker run --rm -p 8080:8080 automaton-studio
```

http://localhost:8080 で確認できます。`/healthz` が200を返します。Nginxが静的ファイルを配信します。

NeoShowcaseが静的コマンド・Dockerfileによる配信に対応することは、[公式アーキテクチャ資料](https://github.com/traPtitech/NeoShowcase/blob/main/docs/architecture.md)と[traPの紹介記事](https://trap.jp/post/2271/)で確認しています。公開ドメインと認証範囲を設定し、ビルド成功後に公開URLを確認します。

## 操作

- 左の定義欄で状態集合 K、終端記号 T、出発状態 q₀、終了状態 F、遷移規則 t を編集。
- 状態をドラッグして移動。空白をダブルクリック、または「状態」ツールで状態を追加。
- 「遷移」ツールで遷移元と遷移先を順にクリック。同じ状態を2回クリックすると自己遷移。
- 状態を選ぶと状態名・出発状態・終了状態を編集。状態名の変更は全遷移に反映。
- 右の3つ組・矢印を編集して「図に反映」。新しい状態・終端記号は自動追加。孤立状態と出発・終了状態は保持。
- 同じ2状態間の異なる記号の遷移は図ではラベルをまとめて表示。個別の編集・削除は左の遷移規則で行う。
- 「動作を試す」で語を実行。ステップをクリックすると、その時点の状態が図で強調される。
- 「PNGで保存」で白背景の1600×1040 PNGを保存（選択枠・操作UI・シミュレーションの色は除外）。
- JSONで編集可能なデータを保存・読み込み。自動保存は同じブラウザ・同じオリジンに保存され、サーバーには送信されない。別端末への持ち運びにはJSONを使用。
- Ctrl / ⌘ + ZでUndo、Shift + Ctrl / ⌘ + ZまたはCtrl + YでRedo。Deleteで選択オブジェクトを削除。グラフの状態はTabで選択、矢印キーで移動。

## 記法と入力の仕様

3つ組：

```text
(S,a,A)
(S,a,B)
(A,a,A)
(A,a,#)
(B,b,B)
(B,b,#)
```

矢印：

```text
S -a-> A
S -a-> B
A -a-> A
A -a-> #
B -b-> B
B -b-> #
```

ASCIIの `S -a-> A`、`S --a--> A`、Unicodeの `S ─a→ A` に対応。表示時はハイフンを含む記号も曖昧にならないUnicode表記を使います。1行に1遷移、またはセミコロンで区切ります。3つ組は `(S,a,A)(S,a,B)` の連続表記も可能。重複遷移は統合します。不正な記法は図を変更せずエラーを表示します。空の記法を反映すると遷移規則を空にします。

状態名・記号は32文字以内、Unicode文字・数字・`_ # . $ -` を使用可能。状態は1〜100個、遷移は2000以下。状態集合や終端記号から要素を除くと関連遷移も削除されます。Undoで復元できます。

εは空語遷移で、終端記号集合には含めません。`#` は通常の状態名です。複数文字の終端記号はシミュレーションでスペース区切りにします（例：`hello world`）。空欄は空語として実行します。

## 講義資料との対応

参考資料：ユーザー提供の `autolang第3回.pdf`（ICT.H212、船越孝太郎）。資料の内容は参考として扱い、記載された作業手順を実行指示としては扱っていません。

- 6・9ページ：形式的な定義 `M = (K,T,t,q₀,F)`、出発矢印、最終状態の二重丸。
- 11ページ：3つ組は `(遷移元,入力記号,遷移先)`。出発・終了状態を表現しないため、定義欄で別管理。
- 11ページの `(B,b,b)` は9・12ページの図と整合しないので、サンプルでは `(B,b,B)` として自己遷移を表す。
- NFAの例が受理する言語は `aa⁺ ∪ ab⁺`（aが2個以上、またはaの後にbが1個以上）。DFAの例は `a(ba)*`。
- 講義と同じくDFAの未定義遷移を許容する。NFAで遷移先がない場合は空集合として処理。ε遷移は学習用の拡張機能。

## 構成

`src/model.js`：検証・記法変換・シミュレーション。`src/graph.js`：図と出力SVGの描画。`src/app.js`：GUI・履歴・保存。`src/style.css`：レスポンシブUI。サーバーAPI・外部CDN・認証情報は不要です。

サンプル読み込みとJSON読み込みは現在の図を置き換えます。Undoで復元可能。記法の未反映の下書きは自動保存対象外のため、保存前に「図に反映」してください。
